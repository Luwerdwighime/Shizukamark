# CI/CD (GitHub Actions)
Чистые GitHub Actions (без Fastlane на старте).
Папка: .github/workflows/

Триггеры:
- pull_request → main/develop: только quality
- push → main/develop: quality + build-android
- push тега v*: quality + build-android + GitHub Release
- workflow_dispatch: ручной запуск

Джобы:
1. quality (ubuntu-latest): format + analyze + test + coverage
2. build-android (ubuntu-latest, needs: quality): signed APK + AAB, upload-artifact. При теге — GitHub Release.
3. build-ios — по умолчанию отключена (if: false). Включается только вручную при необходимости.

Секреты (обязательные для Android):
- ANDROID_KEYSTORE_BASE64
- ANDROID_KEYSTORE_PASSWORD
- ANDROID_KEY_ALIAS
- ANDROID_KEY_PASSWORD

Кэширование: Flutter SDK, pub, Gradle.
Flutter version фиксируется в workflow.
Десктоп-билды и iOS-билды по умолчанию отключены.

## Бинарник audiowmark
- Репозиторий audiowmark: https://github.com/swesterfeld/audiowmark.
- Сборка нативного компонента под Android NDK:
  - Скрипт сборки (Dockerfile / bash-скрипт с Android NDK toolchain) компилирует audiowmark со статическим линкованием всех C++ зависимостей (FFTW3, libsamplerate, libsndfile).
  - Результат сборки: `libaudiowmark.so` под целевые архитектуры: `arm64-v8a`, `armeabi-v7a`, `x86_64`.
  - Сборка нативного бинарника вынесена в отдельный GitHub Actions workflow (`build-native`), чтобы не пересобирать тяжелые C++ зависимости на каждый коммит Flutter. Артефакты кэшируются или загружаются из GitHub Releases.
- Размещение в проекте: готовые файлы помещаются в `android/app/src/main/jniLibs/<abi>/libaudiowmark.so`.
- В `AndroidManifest.xml` прописывается `android:extractNativeLibs="true"`, благодаря чему система при установке APK извлекает файл в `context.applicationInfo.nativeLibraryDir` с правами исполнения, что полностью совместимо с политикой W^X и SELinux на Android 10+ (API 29+ / SDK 34).
- На Linux/Windows/macOS (когда будут) — аналогично, со своими статическими бинарниками/библиотеками.

## Детализация шагов для Android и GitHub Actions
- Используемый action для Flutter: `subosito/flutter-action@v2` с параметрами `channel: 'stable'` и `flutter-version: '3.27.x'`.
- Используемый action для Java: `actions/setup-java@v4` с параметрами `java-version: '17'` и `distribution: 'temurin'`.

Последовательность шагов (steps) в джобе `build-android`:
1. Checkout исходного кода (`actions/checkout@v4`).
2. Настройка Java 17 и Flutter SDK.
3. Кэширование папок `~/.pub-cache` и `~/.gradle/caches`.
4. Подгрузка скомпилированных `libaudiowmark.so` в `android/app/src/main/jniLibs/` (из кэша или релизов workflow `build-native`).
5. Выполнение `flutter pub get`.
6. Декодирование Keystore из Secrets в файл приложения:
   `echo "${{ secrets.ANDROID_KEYSTORE_BASE64 }}" | base64 --decode > android/app/keystore.jks`
7. Генерация файла `android/key.properties` перед сборкой:
   - storePassword=${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
   - keyPassword=${{ secrets.ANDROID_KEY_PASSWORD }}
   - keyAlias=${{ secrets.ANDROID_KEY_ALIAS }}
   - storeFile=keystore.jks
8. Выполнение команд сборки: `flutter build apk --release` и `flutter build appbundle --release`.
9. Выгрузка артефактов (`actions/upload-artifact@v4`): сохранять `build/app/outputs/flutter-apk/app-release.apk` и `build/app/outputs/bundle/release/app-release.aab`.
10. При наличии тега `v*` — публикация через `softprops/action-gh-release@v2` с автоматически прикрепленными `.apk` и `.aab` файлами.
