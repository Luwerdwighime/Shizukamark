# Интеграция с audiowmark

- Бинарник: абсолютный путь = getApplicationSupportDirectory() + "/audiowmark".
- Рабочая директория процесса: всегда getApplicationDocumentsDirectory().
- Все пути в аргументах — относительные от getApplicationDocumentsDirectory().
- Запуск: Process.run(absoluteBinaryPath, args, workingDirectory: docsDir) внутри Isolate/compute.
- При ненулевом exitCode или непустом stderr → Result.error с текстом stderr (или "Код ошибки audiowmark: "+{exitCode}).

- Требуется класс-обёртка Audiowmark.
- Keys использует Audiowmark для создания ключей.
- StegoProcessor использует Audiowmark для наложения водяных знаков.
- Бинарник audiowmark собирается при билде проекта с полностью статическим линкованием, на линкование ОС юзера мы не рассчитываем.

## Создание ключа
- Команда: ["gen-key", "--key", "keys/$fileName.key", "--name", name]
- fileName = 8 lowercase hex (SHA-256 от 16 случайных байт) + расширение ".key".
- После успешного завершения файл обязан существовать.
- Возвращаем структуру: {name, path}.

## Создание водяного знака
- Команда: ["add", "in.wav", "out.wav", "--key", keyPath, hash32]
- keyPath вида "keys/xxxxxxxx.key"
- После успеха out.wav обязан существовать.

## Чтение водяного знака
- Список всех ключей из Keys.listKeys().
- Базовая команда: ["get", "in.wav"] + для каждого ключа ["--key", keyPath].
- Если patient == true → добавить ["--detect-speed-patient", "--n-best", "32"].
- Парсинг stdout:
  - Ищем строки, начинающиеся с "pattern".
  - Третье поле (разделитель пробел) — 32-символьный lowercase hex-хэш.
  - Для каждого найденного хэша сразу ищем в Messages по hash.
  - Первое совпадение → возвращаем msg.
  - Если ни одного совпадения → "Водяной знак не найден".
- Строки "speed ..." игнорируются.
