#Режимы работы
- После запуска программа показывает стартовый экран с кнопками "Нанести знак", "Прочитать знак", "Известные ключи", "Импорт данных" и "Экспорт данных".
- По аппаратной кнопке телефона "Назад" закрываются любые инструменты, аналогично кнопке "Отмена" на самом инструменте, но режим не меняется.
- Кнопка "Назад" возвращает из любого режима на стартовый экран, если не открыты инструменты.
- Если элементы дизайна превысили высоту экрана, то у всего экрана появляется прокрутка.

---

##Кнопка "Импорт данных"
- Открывается файловый менеджер ОС для указания zip файла для импорта.
- При ошибке toast: "zip архив с неправильным содержимым". (Неправильное содержимое - это отсутствие `messages.sqlite` и папки keys.)
- При успехе: "Данные успешно импортированны."

---

##Кнопка "Экспорт данных"
- Открывается файловый менеджер ОС для указания zip файла для экспорта.
- Создаётся zip, согласно разделу "Ядро/Создание zip для экспорта".

##Режим "Нанести знак"

###Дизайн "Нанести знак"
На экране сверху вниз 7 элементов на всю ширину:
1. textarea с hint text "Введите секретное сообщение". Высота 4 строки, растягивается по вертикали при заполнении текстом.
2. модуль выбора в ФС (МФС) для музла, hint "Выберите музло".
3. модуль выбора ключа (МВК), hint "Выберите ключ".
4. серым hint шрифтом центрированно по экрану "или".
5. кнопка "Создать новый ключ".
6. МФС для папки экспорта, hint "Выберите папку экспорта".
7. снизу экрана кнопка "Наложить водяной знак"

###Кнопка "Создать новый ключ"
Запускает инструмент создания ключа (ИСК). При успешном окончании работы инструмента, имя ключа появляется в п.3 дизайна интерфейса, а сгенерированный и сохранённый в библиотеку ключ считается выбранным для работы кнопки "Наложить водяной знак".

###Кнопка "Наложить водяной знак"
- Проверяем секретное сообщение: непустая строка printable Unicode. Иначе toast "Введите секретное сообщение".
- Хэш секретного сообщения вычисляется как первые 32 символа hex-представления SHA-256 от UTF-8 байт секретного сообщения (эквивалент `echo -n "$msg" | sha256sum | head -c 32`).
- Проверяем входящее музло, если нет — toast "Выберите музло".
- Проверяем, что ключ выбран, если нет — toast "Создайте или выберите ключ".
- Проверяем папку экспорта, если нет — toast "Выберите папку экспорта".

- Открывается диалог выбора выходного кодека (падающий список):
  **Lossy (современные):**
  - AAC (рекомендуется)
  - Opus
  - MP3
  **Lossless:**
  - FLAC
  - WAV (PCM 16-bit)
  - ALAC
- После выбора кодека показывается прогресс операций. Выполняются процессы.
- AudioProcessor декодирует входной файл во временный WAV (in.wav).
- StegoProcessor читает in.wav, накладывает водяной знак и сохраняет результат в out.wav.
- AudioProcessor кодирует out.wav в выходной кодек, указанный юзером, и сохраняет его в указанное юзером место.
- Имя выходного файла = имя входного файла без расширения + "_wm." + расширение выбранного кодека.
- Временные in.wav и out.wav удалются.
- При ошибке — toast соответственно: "Ошибка декодирования", "Ошибка наложения водяного знака", "Ошибка сжатия кодеком", "Ошибка сохранения". Остаёмся в режиме "Нанести знак".
- При успехе:
  - Запись message/hash/ts в Messages.
  - Переключаемся на стартовый экран, toast "Файл успешно сохранён: "+{/путь/до/файла}.
  - Если путь относителен относительно юзерского пространства (Android, iOS), то так и пишем: "Файл успешно сохранён: Home/"+{/путь/до/файла}.

##Режим "Прочитать знак"

###Дизайн "Прочитать знак"
На экране сверху вниз 5 элементов на всю ширину:
1. МФС для музла с секретным сообщением, hint: "Выберите помеченное музло".
2. Серым hint шрифтом: "Не забудте предварительно импортировать данные от создателя водяного знака, чтобы смочь прочитать его."
3. Нередактируемая textarea с hint text "Здесь будет секретное сообщение". Высота 4 строки, растягивается по вертикали при заполнении текстом (заполняется автоматически по кнопке "Прочитать водяной знак").
4. Галочка переключателя: "Использовать усердное чтение".
5. Снизу экрана кнопка "Прочитать водяной знак".

###Кнопка "Прочитать водяной знак"
- Проверяем входящее музло, если нет — toast: "Выберите помеченное водяным знаком музло".
- Показывается прогресс операций. Выполняются процессы.
- AudioProcessor декодирует входной файл во временный WAV (in.wav).
- StegoProcessor читает знак, галочка "усердное чтение" передатся как параметр patient == true.
- Если одна из ошибок процесса чтения знака (декодирование, извлечение стего) — соответственно toast "Ошибка декодирования", "Ошибка извлечения стего".
- Если водяной знак не найден (поиск выполняется в классе Audiowmark) - toast: "Водяной знак не обнаружен, или у вас нет к нему ключа."
- Если знак найден и сообщение успешно дешифровано — заполняем textarea из п.3 дизайна полученным сообщением.
- Не выходим из режима "Прочитать знак" ни при ошибках, ни при успехе.
- in.wav удаляется перед завершением работы процессов.

##Режим "Ключи"
Является UI для менеджера ключей класса Keys.

###Дизайн "Ключи"
На экране сверху вниз 4 элемента на всю ширину и высоту:
1. Многострочный пролистываемый список ключей.
2. Кнопка "Создать новый ключ".
3. Кнопка "Импорт данных".
4. Кнопка "Экспорт данных".

###Список ключей
- Вместо пустого списка ключей центрированно по вертикали и горизонтали на его месте "Ключей пока нет."
- Строчки в непустом списке отсортированы по алфавиту по имени ключа. Безымянные ключи в конце списка.
- Каждая строка списка состоит из двух элементов: 
  - С правого края экрана кнопка с UTF крестом, ширина строго под кнопку.
  - С левого края на всю доступную оставшуюся ширину неизменяемое текстовое поле, в котором имя ключа.

###Кнопка с крестом
- При нажатии спрашивается согласие: 'Вы действительно хотите удалить сохранённый ключ "{имя_ключа}"?', кнопки "Ок" и "Отмена".
- При подтверждении файл ключа удаляется из keys, строка исчезает из списка.

###Кнопка "Создать новый ключ"
Запускается ИСК. При успехе обновляется список ключей.

###Кнопка "Импорт данных"
Работает аналогично кнопке "Импорт данных" на главном экране.

###Кнопка "Экспорт данных"
Работает аналогично кнопке "Экспорт данных" на главном экране.

#Модули дизайна
- Дизайн составляется из стандартных элементов и модулей. Модули повторно используемые.
- Если тексты подсказок/имён/путей не вмещаются — перенос по словам, расширение родительских блоков дизайна по вертикали.

##Модуль выбора в ФС (МФС)
- Поле в одну строку: нередактируемое текстовое поле + кнопка с UTF-лупой.
- Кнопка запускает стандартный файловый менеджер ОС.
- Пока ничего не выбрано — hint серым. После выбора — путь обычным шрифтом.

##Модуль выбора ключа (МВК)
- Поле в одну строку: нередактируемое текстовое поле + кнопка с UTF-лупой.
- Пока ключ не выбран — hint серым.
- По нажатии запускается ИВК.
- При успехе в поле отображается: имя ключа обычным шрифтом.

#Инструменты

##Инструмент выбора ключа (ИВК)
- Всплывающее меню с пролистываемым списком имён ключей.
- Выбор по клику → возвращает структуру {name, path}.

##Инструмент создания ключа (ИСК)
- Всплывающее окошко ввода имени ключа: непустая строка printable Unicode, длина 1–128 символов. Кнопки "Ок" и "Отмена".
- При пустом/невалидном вводе — подсветка ошибки, нельзя нажать "Ок".
- Файл ключа генерируется и сохраняется в папке keys (выполняется классом Keys).
- Возвращает объект {name, path}.
